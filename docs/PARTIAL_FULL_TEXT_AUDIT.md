## Policy and implementation

Before: any failed PDF among the discovered URLs stopped the entire snippet
retrieval stage before GROBID. Missing XML also stopped the corpus.

After: every candidate remains in `snippet_papers.json`. Unavailable PDFs carry
explicit download/evidence statuses, IDs, metadata, abstracts, snippets with
source/citation provenance, attempted URLs and recorded failures. Successfully
downloaded files proceed to GROBID. Individual parse failures retain limited
evidence; unhealthy/systemically failing GROBID and genuine search/metadata
failures still fail the stage. The coverage report and stage checkpoint distinguish
completion, successful searches with no candidates, and retrieval failure.

`SCHOLAREVAL_FULL_TEXT_POLICY=available-evidence` is the default.
`require-full-text` optionally requires one successfully parsed document. No
percentage is used to infer scientific validity or absence of prior art.
Download attempt budgets survive resume; readable files are never redownloaded.
Parse results are checkpointed by document and parser/config hashes.

The installed GROBID client caught `IOError` before `RequestException`, which
misclassified read timeouts as HTTP 400 file errors. The bounded client now
classifies transport exceptions before that handler. The original recursive
503 retry remains bounded by the existing helper.

The fork already had TLS verification restored when this task began. Historical
code used `verify=False`/`ssl=False` broadly for downloader fallbacks, without a
certificate-specific justification. Verification remains enabled throughout; no
warning suppression or insecure retry was introduced. HTTP/non-PDF-content and
certificate failures are retained in download diagnostics. No
`InsecureRequestWarning` occurred in the actual smoke downloads. Legacy Unicode
status symbols also generated a console encoding error during failed-download
logging; underlying HTTP and non-PDF response reasons remain in the journal.

## Resume the full pipeline

Run from the repository in a shell with the user's working `S2_API_KEY` configured.
This command intentionally permits downstream Astra inference; it was **not run**
during this task. The guarded equivalent was tested successfully.

```powershell
$env:SCHOLAREVAL_LLM_BACKEND = 'codex'
$env:SCHOLAREVAL_CODEX_MODEL = 'auto'
$env:SCHOLAREVAL_CODEX_REASONING = 'high'
$env:SCHOLAREVAL_FULL_TEXT_POLICY = 'available-evidence'
$env:SCHOLAREVAL_GROBID_WORKERS = '1'
$env:SCHOLAREVAL_GROBID_PARSE_TIMEOUT_SECONDS = '300'
.venv/Scripts/python.exe -m ScholarEval.ScholarEval --research_idea demo_data/astra-test-1/soundness/research_plan.txt --llm_engine_name auto --save_to demo_data/astra-test-1 --resume
```
